# Nftables-Script

Простой файрвол для VPN-сервера на nftables. Пускает на ваши порты (обычно 443) только посетителей из России, а сканеры, боты и «ведомственные» сети отбрасывает. Ставится одной командой, настраивается через меню `fw-menu` на русском, списки обновляет сам.

- **Геофильтр.** На выбранные порты пускают только российские адреса (база [zkeen-ip](https://github.com/jameszeroX/zkeen-ip), см. [Благодарности](#благодарности)).
- **Блок-листы.** Известные сканеры и сети некоторых ведомств отбрасываются.
- **Страховка.** Правила применяются с подтверждением и сами откатываются, если вы не подтвердили.
- **Помощь с SSH.** Меню создаёт SSH-ключ, помогает отключить вход по паролю и показывает, кто перебирает пароли.

Порт SSH файрвол не трогает (если вы сами не включили [ограничение частоты](#ssh-защита-от-перебора-и-вход-по-ключу)). В примерах `ip` означает ваш адрес, `port` порт.

## Установка

Нужен сервер (VPS) с root и работающий VPN или прокси (3x-ui, RemnaWave, wg, mihomo и т. п.). Проверено на Ubuntu 24.04; `nftables`, `python3` и `curl` установщик доставит сам.

```bash
curl -fsSL https://raw.githubusercontent.com/J0ll1er/Nftables-Script/main/fw-install.sh -o fw-install.sh
sudo bash fw-install.sh
```

1. Установщик покажет найденные порты и спросит, какие закрывать для не-россиян. Всё верно: Enter. Адрес, с которого вы зашли по SSH, он добавит в доверенные. Правила пока **не включены**.
2. Запустите `fw-menu` → **4** → **2** и ответьте `да`.
3. У вас 60 секунд, чтобы проверить доступ (откройте панель, подключитесь клиентом) и ещё раз ввести `да`. Не подтвердили или сервер перезагрузился: правила **сами откатятся**.
4. Готово, если видите `ИТОГ: ВСЁ В ПОРЯДКЕ`. Списки обновляются раз в сутки сами.

Сначала посмотреть, что будет, ничего не меняя: `fw-menu` → 4 → 1. Фраза **«применить правила»** ниже везде значит: `fw-menu` → 4 → 2, затем `да`. После изменений меню само предложит это сделать.

## Меню `fw-menu`

| Пункт | Что внутри |
| --- | --- |
| **1. Статус и наблюдение** | Статус файрвола (коротко; подробный экран — 1 → 5); «Кто стучится» (что отбросил файрвол, кто и откуда); журнал ошибок; что ещё есть на сервере (ufw, чужие таблицы, открытые порты) |
| **2. Настроить доступ** | Доверенные IP (добавить, показать, удалить); порт управления и разрешённые IP; ограничение частоты SSH; SSH-ключ и вход по паролю |
| **3. Настроить блокировки** | ASN, свои IP и подсети, свои списки по ссылке с GitHub, пресеты |
| **4. Проверить и применить правила** | Пробная проверка без изменений; применение с подтверждением и автооткатом; расписание обновления |
| **5. Версии и обновление** | Что нового, обновление, откат, уведомление о новой версии при входе |
| **6. Отключить или удалить** | Снять правила и автообновление; удалить скрипт и настройки |

Вверху главного меню в рамке видно состояние: загружены ли правила, чем закончилось последнее обновление, сколько доверенных адресов, когда следующее обновление.

### Доверенные адреса (2 → 1)

Доверенный адрес проходит всегда, мимо геофильтра и блок-листов. Вводятся через пробел: `ip`, `ip/24`, DDNS-имя или `ssh` (адрес текущего подключения). Адреса, которые добавил установщик, помечены датой.

Записи **сами не удаляются**, а адреса бывают нестабильными: провайдер меняет IP, и старый достаётся другому человеку; «серый» адрес (CGNAT) или общий выход прокси используют сразу многие. Такой посторонний получит ваши права. Не держите динамические и общие адреса дольше нужного. Свои адреса можно писать в `/opt/fw/trusted.local.txt` (по одному на строку).

**Адрес меняется.** Заведите DDNS-имя (DuckDNS, No-IP, Dynu), добавьте его как доверенный (2 → 1), примените правила и поставьте обновление раз в 3 часа (4 → 3 → `3`). После смены IP доступ вернётся при ближайшем обновлении. Если DDNS недоступен, до 72 часов работают последние известные адреса.

### Какие порты закрывать

Установщик спрашивает порты геофильтра, то есть те, на которые ходят ваши клиенты. Обычно `443`. Позже их можно изменить строкой `GEO_PORTS="443 port"` в `/opt/fw/local.conf` (затем применить правила).

- Порты вне списка остаются **открытыми для всех**: клиенты ходят на 8443, а в списке только 443, значит 8443 не защищён.
- Порт 80 не добавляйте: проверка сертификатов Let's Encrypt приходит из-за границы, продление перестанет работать.
- **Порт SSH в список не добавляйте:** иначе вход будет только из России и с доверенных адресов. Если он окажется в списке, установщик и обновления предупредят (`ЕСТЬ ЗАМЕЧАНИЯ`), но не заблокируют.
- Откроет ли порт вообще, решает ufw или другой файрвол сервера: порт должен быть разрешён и там.

## SSH: защита от перебора и вход по ключу

Всё это необязательно и ничего не делает, пока вы сами не включите.

**SSH-ключ (2 → 6 → 1).** Сервер создаёт ключ ed25519, добавляет публичную часть в `authorized_keys` и показывает приватную с готовой командой `scp` (адрес, порт и пользователь подставляются сами). Скопируйте ключ на компьютер или в Termius. Приватная часть удаляется с сервера после первого входа этим ключом, а если вход не состоялся, через сутки. До этого её можно показать ещё раз. В том же разделе: список ключей (с каких адресов входили, в сети ли ключ сейчас) и удаление.

**Вход по паролю (2 → 6 → 5 и 6).** Отключается только если вы сами сейчас вошли по ключу. Затем нужно зайти по ключу во втором окне и подтвердить; если не подтвердили за 2 минуты, вход по паролю **возвращается сам**. Консоль хостера продолжает работать. Вернуть пароль можно пунктом 6.

**Кто стучится на SSH.** Если пароль выключен, в «Кто стучится» появляется блок «Перебор на SSH»: адреса, число подключений, владелец адреса и пробованные логины. В списке ключей видны и успешные входы за сутки (способ, пользователь, адрес).

**Ограничение частоты (2 → 5).** С одного адреса пропускается не больше N **новых** SSH-подключений в минуту (рекомендуется 20), лишние отбрасываются; через минуту доступ возвращается. Открытые сессии, доверенные адреса и `LAN_ALLOW` под лимит не попадают. Для IPv6 лимит общий на сеть /64. При включении меню проверит, что ваш адрес доверенный, чтобы вы не закрыли себя; заблокировали себя: подождите 5 минут или зайдите с доверенного адреса или через консоль хостера. Порты берутся из `sshd -T` или из `SSH_PORTS="22 port"`.

**Список blocklist.de (2 → 7).** Включён по умолчанию (отключается в этом же пункте). Адреса, которых за последние 48 часов заметили в переборе SSH на чужих серверах, не смогут подключаться к портам SSH вашей ноды. На остальные порты это не влияет, доверенные адреса проходят раньше списка. По моей ноде за сутки в списке оказалось 58 из 64 адресов, которые перебирали SSH, поэтому польза заметная. Минус: под одним адресом иногда сидят много людей (мобильный интернет, общий NAT), и тогда блокировка заденет всех. Свой адрес для входа добавьте в доверенные. Список обновляется каждые 6 часов отдельно от остальных списков (пока включено автообновление; после перезагрузки сервера цепочка запускается заново при ближайшем суточном обновлении), а также при суточном обновлении правил; если скачать не вышло, остаётся прежний список (кэш живёт не дольше трёх суток). При первой установке установщик спрашивает, включать ли список (без диалога: `FW_BLOCKLIST_SSH=да|нет`). Если на сервере отключён вход по паролю, статус и настройка скажут, что список защищает дополнительно. В «Кто стучится» видно, сколько попыток отбито, а в блоке «Перебор на SSH» такие адреса помечены.

## Кто стучится (1 → 2)

Показывает, на какие порты и с каких адресов отбрасывались пакеты: сканеры и ведомства (любые порты), адреса из других стран (защищённые порты), превысившие лимит SSH, а при выключенном пароле ещё и перебор на SSH. Для каждого адреса: владелец (RIPEstat, при необходимости RDAP), страна, AS. Счёт ведёт сам nftables, записи живут до 7 дней, общего сброса нет (экран пишет, когда сотрётся самая старая запись). Это отдельные пакеты, а не подключения: много стука на порт повода для тревоги не даёт, пакеты уже отброшены.

## Обновление

- Меню: `fw-menu` → 5 → 2. Перед установкой проверяется контрольная сумма из описания релиза; если не совпала, установка не запускается. Обновление скрипта **правила не меняет**: они применяются только через 4 → 2.
- Откат: 5 → 3 (к локальной копии из `/root/fw-rollbacks` или к версии с GitHub). Версия: `fw-menu --version`.
- **Уведомление при входе.** Если вышла новая версия, при входе по SSH появляется строка «Файрвол: вышла версия X (у вас Y)». Включается при первом запуске меню, выключается пунктом 5 → 4. При входе скрипт только читает небольшой файл `/opt/fw/latest-version.json`, проверку на GitHub раз в сутки делает в фоне. Сообщение видят все, кто входит на сервер.

Версии `1.2.3`: первая цифра растёт при несовместимых изменениях, вторая при новых возможностях, третья при исправлениях. Каждая версия отмечена тегом `vВЕРСИЯ`, изменения в [CHANGELOG.md](CHANGELOG.md).

## Если пропал доступ или сменился IP

**SSH файрвол не трогает**, поэтому на сервер вы зайдёте. Добавьте новый адрес:

```bash
echo "ip" >> /opt/fw/trusted.local.txt
/opt/fw/update-fw.sh
```

Вторая команда применяет правила **сразу**, без подтверждения и отката. С откатом: `fw-menu` → 2 → 1 → `ip`, затем 4 → 2. Если новый адрес российский, ничего делать не нужно.

**SSH недоступен** (закрыт в ufw или у хостера): откройте веб-консоль в панели хостера (VNC), войдите под root и выполните те же команды. Если вставка не работает: `nano /opt/fw/trusted.local.txt`, допишите адрес, Ctrl+O, Enter, Ctrl+X, затем `/opt/fw/update-fw.sh`. Временно отключить файрвол: `fw-menu` → 6 → 1 (команда `nft delete table inet fw` не подходит: правила вернутся при обновлении или после перезагрузки).

## Как скрипт защищает от ошибок

- **Подтверждение и откат:** 60 секунд на проверку, нет подтверждения или была перезагрузка: правила откатываются.
- **Проверка списков:** пустой, странный или резко изменившийся список не принимается вслепую; если свежий не скачался, берётся кэш.
- **База российских адресов** с сетью шире /8 (IPv4) или /16 (IPv6) отклоняется как неполная, подмена не откроет порты миру.
- **Широкие сети** в блок-листах сами не блокируются: меню спрашивает. Правильный ответ почти всегда Enter (сеть остаётся открытой); `да` только если сеть вам точно не нужна.
- **Итог `ИТОГ:`** после каждого обновления: зелёный `ВСЁ В ПОРЯДКЕ`, жёлтый `ЕСТЬ ЗАМЕЧАНИЯ`, красный `ОШИБКА`. Цвет отключается `NO_COLOR`; результат лежит в `/opt/fw/last-result` (`ok`, `warn`, `error`).

## Настройки

Основное в `/opt/fw/fw.conf`. Свои значения пишите в `/opt/fw/local.conf`: он главнее и не пропадает при обновлении. Большинству ничего менять не нужно.

| Переменная | По умолчанию | Что значит |
| --- | --- | --- |
| `GEO_PORTS` | задаётся при установке | Порты геофильтра |
| `LAN_ALLOW` | пусто | Сети, которые пропускаются без проверок (например, частная сеть хостера) |
| `CONFIRM_TIMEOUT` | `60` | Секунд на подтверждение при ручном применении |
| `SSH_RATE_LIMIT` / `SSH_PORTS` | `0` / авто | Лимит новых SSH-подключений в минуту (от 5; `0` выключено) и порты SSH |
| `BLOCKLIST_SSH` | `1` | `0` выключает блокировку адресов из списка blocklist.de на портах SSH |
| `MAX_GROWTH` / `MIN_KEEP` | `3` / `0.2` | Список, выросший больше чем в 3 раза или уменьшившийся меньше чем до 20%, отвергается |
| `MAX_CACHE_DAYS` / `DDNS_CACHE_HOURS` | `14` / `72` | Сколько жить на кэше, если свежее не скачалось |
| `MIN_PREFIX4` / `MIN_PREFIX6` | `8` / `16` | Порог «слишком большой сети» в блок-листах |
| `MAX_GEO_BYTES` / `MAX_LIST_BYTES` | `50000000` / `20000000` | Предельный размер скачиваемого ответа в байтах |

## Мониторинг

`fw-menu --check` (от root) печатает одну строку и завершается кодом: `0` (`ok`) всё работает, `1` (`warn`) есть замечания или не работает таймер, `2` (`error`) таблица `inet fw` не загружена или обновление провалилось. Подходит для Uptime Kuma (монитор Push) через cron:

```bash
*/5 * * * * root out=$(/usr/local/sbin/fw-menu --check); c=$?; s=up; [ $c -eq 2 ] && s=down; curl -fsS -m 10 --get "https://KUMA/api/push/TOKEN" --data-urlencode "status=$s" --data-urlencode "msg=$out" >/dev/null
```

## Как это устроено внутри

- Правила лежат в отдельной таблице nftables `inet fw`; чужие правила (ufw, WARP и т. п.) скрипт не трогает.
- Снимок правил в `/opt/fw/fw.nft`; после перезагрузки его поднимает `fw-update.service`.
- Ручное применение сначала пишет `fw.nft.pending` и переносит в `fw.nft` только после подтверждения; обновления по таймеру пишут `fw.nft` сразу.
