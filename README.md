# Nftables-Script

Простой файрвол для VPN-сервера: пускает на ваши порты (обычно 443) только посетителей из России, а сканеры, боты и «ведомственные» сети отбрасывает. Ставится одной командой, настраивается через меню `fw-menu` на русском, списки обновляет сам.

Что он делает:

1. **Геофильтр.** На выбранные порты пускает только российские адреса (база [zkeen-ip](https://github.com/jameszeroX/zkeen-ip), см. [Благодарности](#благодарности)).
2. **Блок-листы.** Отбрасывает известных сканеров и сети некоторых ведомств.
3. **Страховка.** Правила применяются с подтверждением и сами откатываются, если вы не подтвердили.

Порт SSH файрвол не трогает (если вы сами не включили [ограничение частоты](#защита-ssh-от-быстрого-перебора-паролей)).

В примерах ниже `ip` означает ваш адрес, `port` порт, `ip:port` пару «адрес и порт». Подставьте свои значения.

## Установка

Нужен свой сервер (VPS) с root и работающий VPN или прокси (3x-ui, RemnaWave, wg, mihomo и т. п.). Проверено на Ubuntu 24.04. Установщик сам доставит `nftables`, `python3`, `curl`.

```bash
curl -fsSL https://raw.githubusercontent.com/J0ll1er/Nftables-Script/main/fw-install.sh -o fw-install.sh
sudo bash fw-install.sh
```

1. Установщик определит, что у вас стоит, покажет порты и спросит, какие закрывать для не-россиян. Всё верно: Enter. Он добавит в доверенные адрес, с которого вы зашли по SSH. Правила пока **не включены**.
2. Запустите `fw-menu` → **4** → **2** («Применить правила и включить таймер»), ответ `да`.
3. У вас 60 секунд, чтобы проверить доступ (откройте панель, подключитесь клиентом) и ещё раз ввести `да`. Не подтвердили или сервер перезагрузился, правила **сами откатятся**.
4. Готово, если видите `ИТОГ: ВСЁ В ПОРЯДКЕ`. Списки обновляются раз в сутки сами.

Сначала посмотреть, что будет, ничего не меняя: `fw-menu` → 4 → 1.

Фраза **«применить правила»** в этой инструкции всегда значит: `fw-menu` → 4 → 2, затем `да`. После добавления или удаления адресов и списков меню само предлагает применить правила: ответьте `да`, и искать пункт 4 → 2 не нужно.

## Меню `fw-menu`: примеры по пунктам

Вверху главного меню в рамке видно состояние: загружены ли правила, чем закончилось последнее обновление, сколько доверенных адресов, когда следующее обновление.

### 1. Статус и наблюдение (только чтение)

| Пункт | Что показывает | Пример |
| --- | --- | --- |
| 1. Статус файрвола | Итог сверху, затем файлы, профиль сервера, настройки, таймер и правила простым языком со счётчиками | `ИТОГ: ВСЁ В ПОРЯДКЕ — файлы на месте, правила загружены, таймер активен, расхождений нет` |
| 2. Кто стучится | Что отклонил файрвол: порты, адреса, владельцы | блоки «Сканеры…», «Из других стран…», «Превысили лимит SSH» |
| 3. Журнал ошибок | Ошибки обновлений | `ошибок не было` |
| 4. Что ещё есть на сервере | Чужие таблицы nft, ufw, открытые порты, SSH, порт 80 и сертификаты | |

В статусе под каждым пунктом проверки, который что-то отбрасывает, стоит счётчик:

```
5. Сканеры и сети ведомств — отбрасываются на всех портах.
   Отброшено пакетов: 115, 6,1 КиБ
```

### 2. Настроить доступ

**1. Добавить доверенные IP или подсети через пробел** (доверенный проходит всегда, мимо геофильтра и блок-листов):

```
IPv4, IPv6, CIDR или DDNS-адрес через пробел (или ssh для текущего подключения): ip
IPv4, IPv6, CIDR или DDNS-адрес через пробел (или ssh для текущего подключения): ip ip/24 name.duckdns.org
IPv4, IPv6, CIDR или DDNS-адрес через пробел (или ssh для текущего подключения): ssh
```

**2. Показать доверенные адреса.** Адреса, добавленные установщиком, помечены датой.

**3. Удалить доверенные адреса:** введите номера или адреса через пробел.

```
Номера или адреса через пробел для удаления (Enter — отмена): 2 ip
```

**4. Настроить порт управления и разрешённые IP** (порт панели или ноды, например RemnaWave; доступ только с перечисленных адресов):

```
TCP-порты управления через пробел (Enter — отмена): port
Разрешённые IPv4, IPv6 или подсети через пробел: ip ip/24
```

**5. Ограничить частоту новых SSH-подключений** (необязательно, см. [ниже](#защита-ssh-от-быстрого-перебора-паролей)):

```
Новых подключений в минуту (число от 5, 0 — выключить, Enter — отмена): 20
```

После любой настройки примените правила.

### 3. Настроить блокировки

| Пункт | Что ввести |
| --- | --- |
| 1. Посмотреть подсети ASN и добавить ASN в блокировку | `Номер ASN или прямая ссылка на его страницу:` номер ASN |
| 2. Добавить IP или подсеть в блокировку | `ip` или `ip/24` |
| 3. Добавить свой список по ссылке с GitHub | ссылка на файл списка в репозитории GitHub |
| 4. Включить или выключить пресеты | номер пресета |
| 5. Удалить ручные IP, подсети, ASN или свои списки | номера записей через пробел |

Блокировка по ASN закрывает сразу все адреса сети организации. Пустой `asn.txt` означает, что блокировка по ASN выключена.

### 4. Проверить и применить правила

| Пункт | Что делает | Пример |
| --- | --- | --- |
| 1. Проверить обновление без применения | Пробный запуск, ничего не меняет | `DRY: синтаксис ок, ничего не применено` |
| 2. Применить правила и включить таймер | Применение с подтверждением и автооткатом | `Применить правила…? Введи «да»: да` |
| 3. Настроить расписание обновления | Раз в сутки или каждые N часов | `03:30`, `3` (каждые 3 часа; можно 2, 3, 4, 6, 8, 12), `сброс` |
| 4. Показать пути к файлам на VPS | Где лежат конфиги и снимки | |

### 5. Версии и обновление скрипта

- **5 → 1** показывает версии и что в них исправлено;
- **5 → 2** обновляет до последней: показывает изменения и ставит после `да`;
- **5 → 3** откатывает к локальной копии из `/root/fw-rollbacks` или к версии с GitHub.

Версия: `fw-menu --version`. Перед установкой меню сверяет контрольную сумму скачанного файла с хешем из описания релиза. Если суммы не совпали, установка не запускается; если хеша нет, нужна фраза `без проверки`. Обновление скрипта **правила не меняет**: новые правила применяются только через 4 → 2.

### 6. Отключить или удалить

- **6 → 1** снимает правила и автообновление;
- **6 → 2** удаляет скрипт и настройки (папка переносится в резерв с `restore.sh`).

Команда `nft delete table inet fw` для отключения не подходит: правила вернутся при следующем обновлении или после перезагрузки.

| Что нужно | Что сделать |
| --- | --- |
| Проверить, что всё работает | `sudo fw-menu --check` или `fw-menu` → 1 → 1 |
| Пустить зарубежный адрес | `fw-menu` → 2 → 1 → `ip`, потом применить |
| Убрать лишний доверенный адрес | `fw-menu` → 2 → 3, потом применить |
| Сменился IP, всё закрылось | [Что делать, если сменился IP](#что-делать-если-сменился-ip-или-пропал-доступ) |

| Заблокировать лишнюю сеть | `fw-menu` → 3 |
| Обновить сам скрипт | `fw-menu` → 5 → 2 |
| Временно отключить файрвол | `fw-menu` → 6 → 1 |

## Какие порты закрывать

Установщик спрашивает порты геофильтра, то есть порты, на которые ходят ваши клиенты. Обычно `443`:

```
Порты для геофильтра через пробел [443]: 443 port port
```

Без вопросов: `FW_GEO_PORTS="443 port" sudo -E bash fw-install.sh`. Позже: строка `GEO_PORTS="443 port"` в `/opt/fw/local.conf` и применить правила.

- Порт из списка закрыт и для TCP, и для UDP: не-россияне и не-доверенные отбрасываются.
- Порты вне списка остаются **открытыми для всех**. Клиенты ходят на 8443, а в списке только 443: порт 8443 не защищён.
- Порт 80 не добавляйте: проверка сертификатов Let's Encrypt приходит из-за границы, продление перестанет работать.
- Порты, которые слушают только `127.0.0.1`, добавлять не нужно.
- **Порт SSH в список не добавляйте.** Под геофильтром вход будет только из России и с доверенных адресов, а из-за границы вы себя закроете. Если порт SSH (из `sshd -T`) окажется в `GEO_PORTS`, установщик и каждое обновление предупредят: в итоге будет `ЕСТЬ ЗАМЕЧАНИЯ`. Правила при этом не блокируются, решение за вами.
- Откроет ли порт вообще, решает ufw (или другой файрвол сервера): нужный порт должен быть разрешён и там.

## Защита SSH от быстрого перебора паролей

Необязательно, по умолчанию выключено. С одного адреса пропускается не больше N **новых** SSH-подключений в минуту, лишние отбрасываются. Бот, который стучится сотни раз в минуту, упирается в потолок, человек, который входит раз-два, нет.

```
fw-menu → 2 → 5 → 20        # рекомендуется 20; потом применить правила
```

То же вручную в `/opt/fw/local.conf`: `SSH_RATE_LIMIT=20`. Порты берутся из `sshd -T` (иначе 22), другие задайте `SSH_PORTS="22 port"`.

- Открытые сессии не рвутся. Блокировка не вечная: когда поток утихает, доступ возвращается сам, обычно за минуту.
- Доверенные адреса и `LAN_ALLOW` под лимит не попадают.
- **Не заблокируйте себя.** При включении меню смотрит, с какого адреса вы подключены, и если его нет в доверенных, предупредит и предложит добавить. Пока адрес не доверенный, «Статус файрвола» показывает красное предупреждение. Заблокировали себя: подождите 5 минут или зайдите с доверенного адреса или через консоль хостера и введите `0`.
- Порог должен быть щедрым: при плохой связи один вход шлёт несколько пакетов подряд. Часто открываете много сессий (`rsync`, Ansible, `autossh`), поставьте больше.
- Для IPv6 лимит общий на всю сеть /64.
- Адреса, превысившие лимит, видны в «Кто стучится». Медленный перебор ниже порога там не виден, его ищите в журнале `sshd`.
- Это не замена ключам: вход только по ключам защищает сильнее.

## Доверенные адреса: подводные камни

Доверенный адрес обходит геофильтр и блок-листы. **Записи сами не удаляются**, а адреса бывают нестабильными: провайдер меняет IP, и старый достаётся другому человеку; «серый» адрес (CGNAT) или общий выход прокси используют сразу многие. Такой посторонний получит ваши права. Не держите динамические и общие адреса в доверенных дольше нужного.

Адрес, добавленный установщиком, помечен `# авто, добавлен ДАТА`; старше 14 дней меню предупредит. Свои адреса можно писать в `/opt/fw/trusted.local.txt` (по одному `ip` или `ip/24` на строку).

### Адрес, который меняется: DDNS-адрес

Нужен, только если вы заходите из дома, а провайдер меняет IP. DDNS-адрес (`name.duckdns.org`) всегда ведёт на ваш текущий IP; скрипт хранит имя и сам узнаёт по нему адрес.

1. Заведите адрес на DuckDNS, No-IP или Dynu и настройте обновление IP на роутере (раздел «DDNS») или программой-обновлялкой.
2. `fw-menu` → 2 → 1 → `name.duckdns.org`.
3. Применить правила.
4. `fw-menu` → 4 → 3 → `3`: раз в 3 часа адрес узнаётся заново.

После смены IP доступ вернётся при ближайшем обновлении (до 3 часов). Принимаются только внешние адреса, не больше 8 на имя. Если DDNS недоступен, до 72 часов работают последние известные адреса, итог будет жёлтым. Берегите аккаунт на DDNS-сервисе: кто управляет адресом, тот управляет доступом к серверу. Чаще раза в 2 часа запускать нельзя.

## Что делать, если сменился IP или пропал доступ

**SSH файрвол не трогает**, поэтому на сервер вы зайдёте. Добавьте новый адрес:

```bash
echo "ip" >> /opt/fw/trusted.local.txt
/opt/fw/update-fw.sh
```

Вторая команда применяет правила **сразу**, без подтверждения и отката. С откатом: `fw-menu` → 2 → 1 → `ip`, затем 4 → 2. Если новый адрес российский, ничего делать не нужно.

**SSH недоступен** (закрыт в ufw или у хостера): откройте веб-консоль в панели хостера (VNC, VMC), войдите под root и выполните те же команды. Если вставка не работает или не набираются `>` и `"`: `nano /opt/fw/trusted.local.txt`, допишите адрес, Ctrl+O, Enter, Ctrl+X, затем `/opt/fw/update-fw.sh`.

## Как скрипт защищает от ошибок

- **Подтверждение и откат:** 60 секунд на проверку, нет подтверждения или была перезагрузка, правила откатываются.
- **Проверка списков:** пустой, странный или резко изменившийся список не принимается вслепую; если свежий не скачался, берётся кэш.
- **База российских адресов** с сетью шире /8 (IPv4) или /16 (IPv6) отклоняется как неполная, подмена не откроет порты миру.
- **Широкие сети** в блок-листах сами не блокируются, меню спросит (см. ниже).
- **Итог `ИТОГ:`** после каждого обновления: зелёный `ВСЁ В ПОРЯДКЕ`, жёлтый `ЕСТЬ ЗАМЕЧАНИЯ`, красный `ОШИБКА`. Цвет отключается `NO_COLOR`. Результат лежит в `/opt/fw/last-result` (`ok`, `warn`, `error`).

## Настройки

Основное в `/opt/fw/fw.conf`. Свои значения пишите в `/opt/fw/local.conf`: он главнее и не пропадает при обновлении. Большинству ничего менять не нужно.

| Переменная | По умолчанию | Что значит |
| --- | --- | --- |
| `LAN_ALLOW` | пусто | Сети, которые пропускаются без проверок: `LAN_ALLOW="ip/24"`. Установщик предложит значение, если у сервера адрес из частной сети |
| `CONFIRM_TIMEOUT` | `60` | Секунд на подтверждение при ручном применении |
| `SSH_RATE_LIMIT` | `0` | Новых SSH-подключений в минуту с одного адреса (от 5; `0` выключено) |
| `SSH_PORTS` | авто | Порты SSH для лимита через пробел |
| `MAX_GROWTH` | `3` | Список, выросший больше чем в 3 раза, отвергается |
| `MIN_KEEP` | `0.2` | Список, уменьшившийся меньше чем до 20%, отвергается |
| `MAX_CACHE_DAYS` | `14` | Сколько дней жить на кэше, если свежее не скачалось |
| `DDNS_CACHE_HOURS` | `72` | Сколько часов жить на прежних адресах DDNS |
| `MIN_PREFIX4` / `MIN_PREFIX6` | `8` / `16` | Порог «слишком большой сети» в блок-листах |
| `MAX_GEO_BYTES` / `MAX_LIST_BYTES` | `50000000` / `20000000` | Предельный размер одного скачиваемого ответа в байтах: база российских адресов и всё остальное (списки сканеров, ответы RIPEstat). Ответ крупнее отбрасывается как недоступный источник, остальное работает как обычно |

### Слишком большие сети в блок-листах

Если в чужом списке по ошибке оказалась огромная сеть (целая страна, крупный провайдер), скрипт её **не блокирует**, а при применении или пробной проверке спрашивает:

```
Найдены слишком широкие сети: 1. Сейчас они пропускаются и не блокируются.
Блокировать эти сети? Введи «да», Enter — не блокировать:
```

**Enter** почти всегда правильный ответ: сеть остаётся открытой, меню спросит снова при следующей проверке. `да` отвечайте, только если вся сеть вам точно не нужна: она запишется в `/opt/fw/wide-ok.txt` и будет блокироваться при каждом обновлении (передумали: удалите строку и примените правила).

## Мониторинг: `fw-menu --check`

Печатает одну строку и завершается с кодом (запускать от root):

| Код | Строка | Значит |
| --- | --- | --- |
| 0 | `ok: ...` | правила загружены, последнее обновление без ошибок |
| 1 | `warn: ...` | есть замечания или не работает таймер |
| 2 | `error: ...` | таблица `inet fw` не загружена или обновление провалилось |

Пример для Uptime Kuma (монитор Push) через cron, `KUMA` и `TOKEN` свои:

```bash
*/5 * * * * root out=$(/usr/local/sbin/fw-menu --check); c=$?; s=up; [ $c -eq 2 ] && s=down; curl -fsS -m 10 --get "https://KUMA/api/push/TOKEN" --data-urlencode "status=$s" --data-urlencode "msg=$out" >/dev/null
```

## Кто стучится (1 → 2) и что ещё есть на сервере (1 → 4)

«Кто стучится» показывает, на какие порты и с каких адресов отбрасывались пакеты, отдельно: сканеры и ведомства (любые порты), адреса из других стран (защищённые порты), адреса, превысившие лимит SSH (если он включён). У каждого блока: порты с долей в процентах, «По владельцам» (название блока адресов по RIPEstat, страна, AS; для сканеров название списка), самые активные адреса, строка «впервые замечены за последние сутки». Счёт ведёт сам nftables, записи живут до 7 дней и переносятся при обновлении правил. Это отдельные пакеты, а не подключения. Много стука на какой-то порт повода для тревоги не даёт: пакеты уже отброшены. Ответы RIPEstat хранятся 30 дней в `/opt/fw/owner-cache.json`.

«Что ещё есть на сервере» только читает: чужие таблицы nftables (например, `remnanode`), ufw, открытые наружу порты, порты SSH, состояние порта 80 (хуки certbot, cron, acme.sh).

## Версии

Версия `1.2.3`: первая цифра растёт при несовместимых изменениях, вторая при новых возможностях, третья при исправлениях. Каждая версия отмечена тегом `vВЕРСИЯ`, изменения в [CHANGELOG.md](CHANGELOG.md).

## Как это устроено внутри

- Правила лежат в отдельной таблице nftables `inet fw`. Чужие правила (ufw, WARP и т. п.) скрипт не трогает.
- Снимок правил в `/opt/fw/fw.nft`; после перезагрузки его поднимает `fw-update.service`, а при включённом `nftables.service` ещё и drop-in `/etc/systemd/system/nftables.service.d/10-fw-restore.conf`.
- Ручное применение сначала пишет `fw.nft.pending`, а в `fw.nft` переносит только после подтверждения. Обновления по таймеру пишут `fw.nft` сразу.
