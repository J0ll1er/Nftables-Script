# Nftables-Script

Единый nftables-файрвол для VPN-узлов: гео-фильтр «только Россия» на 443 (TCP/UDP),
блок-листы сканеров и ведомственных сетей, доверенные списки, защита порта управления.

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/J0ll1er/Nftables-Script/main/fw-install.sh -o fw-install.sh
sudo bash fw-install.sh
```

Установщик сам по себе правила не меняет: после установки откройте `fw-menu`, посмотрите
пробное обновление (dry-run) и примените правила. Повторный запуск на узле с установленным
файрволом выполняет обновление с сохранением настроек.

## Порты геофильтра

Установщик спрашивает «Порты для геофильтра через пробел». Если клиенты подключаются на несколько внешних портов, перечислите их все:

```
Порты для геофильтра через пробел [443]: 443 8443 9443
```

Без диалога: `FW_GEO_PORTS="443 8443 9443"`. Список хранится в переменной `GEO_PORTS` в `/opt/fw/fw.conf`; чтобы изменить его позже, добавьте `GEO_PORTS="..."` в `/opt/fw/local.conf` (он переопределяет `fw.conf`) и примените правила через `fw-menu` → 4.

- Каждый порт из списка фильтруется и по TCP, и по UDP: адреса не из России (и не из trusted) отбрасываются.
- Порты, которых в списке нет, остаются открытыми для всех. Если клиент ходит на 8443, а в списке только 443, этот порт геофильтром не защищён.
- Порты, которые слушают только на `127.0.0.1` (внутренние порты nginx, xray, панели), из интернета недоступны, добавлять их не нужно.
- Порт, который должен принимать клиентов не из России, в список не включайте.
- Порт 80 в список лучше не добавлять: проверка Let's Encrypt приходит из-за границы, и продление сертификата сломается.
- Фильтр решает, кого пускать, а откроет ли порт вообще, решает ufw (или другой файрвол): нужный порт должен быть в нём разрешён отдельно.
- Установщик предупреждает о расхождениях: порт слушает снаружи, но не входит в геофильтр, или входит, но его никто не слушает.

## Состав

- `fw-install.sh` — готовый установщик (собирается `build.py`).
- `orig-fw-install.sh` — базовая версия, из которой `build.py` делает сборку.
- `build.py` — применяет правки к установщику, `update-fw.sh` и `fw-menu`, пересчитывает контрольные суммы.
- `tests/` — тесты меню и обновления (нужны root и nftables).

## Сборка

```bash
python3 -I build.py
```

## Настройки

Основные параметры находятся в `/opt/fw/fw.conf`; локальные переопределения можно хранить в
`/opt/fw/local.conf`. Повторная установка сохраняет список ASN: пустой `asn.txt` означает, что
блокировка по ASN выключена.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `LAN_ALLOW` | пусто | Эти сети пропускаются после trusted, до списков сканеров и геофильтра. При новой установке с адресом сервера в RFC1918 или 100.64.0.0/10 установщик предлагает включить только соответствующий диапазон. При обновлении существующей установки значение не меняется; чтобы включить, добавьте `LAN_ALLOW="нужная_подсеть"` в `/opt/fw/local.conf`. |
| `CONFIRM_TIMEOUT` | `60` | Секунды на подтверждение ручного применения правил в `fw-menu`; без подтверждения срабатывает откат. |
| `MAX_GROWTH` | `3` | Максимальный рост числа записей и охваченных адресов свежего списка сканеров или RU IPv4 относительно предыдущего успешного применения. |
| `MIN_KEEP` | `0.2` | Минимальная доля записей и охваченных адресов относительно предыдущего успешного применения. |
| `MAX_CACHE_DAYS` | `14` | Максимальный возраст кэша списков сканеров и ASN в днях. |
| `MIN_PREFIX4` / `MIN_PREFIX6` | `8` / `16` | Самые широкие допустимые внешние префиксы IPv4/IPv6; админский `extra.txt` не ограничивается. |

Сеть шире этого порога пропускается (не блокируется), а остальной список работает. `fw-menu` → «Проверить и применить правила» покажет такие сети и спросит, блокировать ли их. Подтверждённые попадают в `/opt/fw/wide-ok.txt` (по строке на сеть, `#` — комментарий) и блокируются при каждом обновлении, в том числе по таймеру. Неподтверждённые перечислены в `/opt/fw/wide-pending.txt`.

Снимок `/opt/fw/fw.nft` восстанавливается после запуска или перезагрузки `nftables.service`
через drop-in `/etc/systemd/system/nftables.service.d/10-fw-restore.conf`.
Ручное применение сохраняет снимок сначала как `fw.nft.pending` и переносит его в `fw.nft`
только после подтверждения. При откате pending удаляется. Таймерные обновления пишут `fw.nft`
непосредственно. Пункт «Удалить правила и автообновление» удаляет снимок и drop-in.

## Обновление и версии

Версии вида `1.2.3`: первая цифра растёт при несовместимых изменениях, вторая — при новых возможностях, третья — при исправлениях. Каждая версия — git-тег `vВЕРСИЯ`, список изменений — в [CHANGELOG.md](CHANGELOG.md).

В `fw-menu` для этого есть отдельный пункт **7. Версии и обновление скрипта**:

- **7 → 1** — версии и что в них исправлено (показывает только то, что новее установленной);
- **7 → 2** — обновить до последней версии: сначала показываются изменения, установка только после ответа «да»;
- **7 → 3** — откатить скрипт: к локальной копии из `/root/fw-rollbacks` или к выбранной версии с GitHub.

Обновление скрипта правила не меняет: новые правила применяются только через пункт 4 (с подтверждением и автооткатом). Текущая версия: `fw-menu --version`.

## Что ещё есть на сервере

`fw-menu` → 8 только читает и ничего не меняет: показывает чужие таблицы nftables (в том числе `remnanode` от плагинов ноды Remnawave), ufw и заготовленные в нём правила, порты, слушающие снаружи, SSH-порты и состояние порта 80. По порту 80 проверяет хуки certbot (`renewal-hooks` и настройки сертификата), задания cron и наличие acme.sh. Если способ открытия порта на время продления определить нельзя, так и написано.

## Итог запуска

Обновление, пробный запуск и применение через `fw-menu` заканчиваются строкой `ИТОГ:`:
зелёная `ВСЁ В ПОРЯДКЕ`, жёлтая `ЕСТЬ ЗАМЕЧАНИЯ` (с перечнем причин: резервный источник, кэш, нет данных) или красная
`ОШИБКА`. Цвета включаются только в терминале и отключаются переменной `NO_COLOR`. Результат
последнего применения хранится в `/opt/fw/last-result` (`ok`, `warn`, `error`).

## Выпуск новой версии

1. Поднять `VERSION` в `build.py`, добавить раздел `## ВЕРСИЯ` сверху `CHANGELOG.md`, пересобрать (`python3 -I build.py`).
2. Закоммитить в `main`. Тег `vВЕРСИЯ` и страницу релиза с описанием из `CHANGELOG.md` создаст GitHub Actions (`.github/workflows/tag-release.yml`) сам, вручную ничего делать не нужно.
